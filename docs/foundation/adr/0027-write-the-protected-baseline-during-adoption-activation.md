# ADR-0027: Write the protected baseline during adoption activation

| Field | Value |
| -- | -- |
| Status | accepted |
| Date | 2026-10-07 |
| Deciders | repository owner (approved 2026-10-07, PR #82) |

| Supersedes / Superseded by | Amends ADR-0021 (protected files are no longer a hand port when absent) and ADR-0022 (phase 3 writes more files); supersedes none |

## Context

Template Sync never delivers a protected path. A repository created by `bootstrap-child`
starts from a copy of the template, so it already holds every protected file: the
protected `.ai/` documents, `.claude/settings.json` and the guard hook, the protected
skills, `.github/governance/repository.json`, every workflow, `CLAUDE.md`, and
`Taskfile.yml`. A repository adopted under ADR-0021 and ADR-0022 holds none of them after
activation, and ADR-0021 leaves them to a hand port that its plan reports as
`pending_manual_port`.

The inherited tests and `doctor` require those files. Verified on 2026-10-07 with
shared-account-retirement, the first repository adopted from ai-dev-foundation `7762372`,
at its activation commit `c27cc5f` plus the foundation `Taskfile.yml`:

| State | Foundation tests (327) | `doctor` |
| -- | -- | -- |
| After activation | 4 failures, 27 errors | 4 problems |
| Plus the 37 protected files absent from the repository, copied from the parent, and the repository's own `Taskfile.yml` | pass (9 skipped) | pass |

The missing files therefore have to arrive in one pull request. In that repository the
hand port was PR #3: about 1,900 changed lines in 31 files excluding `uv.lock`. GR-020
fails a pull request above 800 lines or 20 files and allows an oversized pull request only
for a mechanical rename or move. PR #3 was merged with `pr-quality` failing, which GR-011
forbids. Splitting it is not possible without failing `doctor` in every intermediate
pull request.

Two facts constrain the design:

- The parent's `Taskfile.yml` cannot be copied. The foundation's required tasks echo
  `[template] <task>: not wired yet`, and `taskfile_profile.py` fails `doctor` outside the
  foundation while any required task does.
- Phase 3 is the first pull request in which `pr-quality` can run, because the protected
  `ci.yml` that defines it does not exist before then. The phase 2 bot pull request is
  already exempt from GR-020 by ADR-0022 for that reason.

## Options considered

### Option 1: Do nothing

Keep the hand port and document that its pull request exceeds GR-020.

- Pros: no code change.
- Cons: every adoption ends with a merge over a failing required check (GR-011); the agent
  that ports the files chooses which parent files to copy and edits them by hand, which is
  the drift ADR-0021 already names as the main risk.

### Option 2: Exempt lines that equal the parent from the size count

`pr_size_policy.py` counts only lines that differ from the parent's file at the lock
commit.

- Pros: works for any pull request, not only adoption; the hand port stays as it is.
- Cons: `pr-quality` must fetch the parent in CI; a private parent requires a credential
  in every child's CI (ADR-0016 keeps fleet credentials out of ordinary jobs); the hand
  port still decides which files to copy.

### Option 3: Port the files in several pull requests

- Pros: each pull request stays within GR-020.
- Cons: `doctor` fails in every pull request except the last, which breaks the "every
  intermediate state is green" rule.

### Option 4: Activation writes the absent protected files, and its pull request is exempt

`adopt-child --apply` copies from the parent every protected file the repository does not
have, takes `Taskfile.yml` from the reviewed payloads, and the size guard recognises the
activation pull request.

- Pros: no hand port for absent files; the tool, not an agent, chooses and copies them;
  every pull request is green; no CI credential.
- Cons: the activation pull request is large and exempt from the hard limit; the copied
  defaults (placeholders in `CODEOWNERS` and `.ai/mission.md`, the release workflow, the
  repository governance policy) need follow-up edits.

## Decision

Option 4. The following extends ADR-0022's phase 3; every other ADR-0021 and ADR-0022
clause stands.

- **Protected baseline.** Phase 3 (`adopt-child --apply`) MUST write, byte-identical to the
  parent at the source commit, every file under the export's `protected_paths` that the
  repository does not have, except:
  - paths written from payloads or generated by activation: `README.md`,
    `.ai/project/agent-overlay.md`, `.github/workflows/template-sync.yml`, `Taskfile.yml`,
    the parent README archive, the manifest, the lock, the agent profile, and
    `.templatesyncignore`;
  - the parent's own project content: `src/`, `tests/`, `docs/adr/`, `CHANGELOG.md`, and
    `docs/handoff.md`.
- **Existing files win.** Activation MUST NOT overwrite a protected file the repository
  already has. Such a file stays a hand port, as ADR-0021 states.
- **`Taskfile.yml`.** When the repository has no `Taskfile.yml`, activation MUST take it
  from the payload directory and MUST refuse when the payload is missing. When the
  repository has one, activation MUST leave it unchanged.
- **Plan.** The read-only plan MUST list the baseline paths phase 3 will write, so the
  owner reviews them before activation.
- **Size exception.** `scripts/pr_size_policy.py` MUST report a hard-limit result as a
  warning, not a failure, when the pull request removes `.github/inheritance/adoption.json`.
  The marker exists only between phase 1 and phase 3 (ADR-0025), so its removal identifies
  the activation pull request. The warning MUST name this ADR. The soft-limit warning and
  the GR-025 checkpoints are unchanged.
- **Review obligation.** The activation pull request MUST say that it is exempt and MUST
  list the baseline paths from the plan; the reviewer compares that list with the files in
  the pull request.

## Consequences

**Positive:**

- An adopted repository passes `doctor` at the activation commit, like a repository
  created by `bootstrap-child`.
- No adoption needs a merge over a failing `pr-quality`.
- The files arrive unedited from a pinned parent commit, so later differences are the
  repository's own edits.

**Negative:**

- GR-020 is not machine-enforced on the activation pull request. Unrelated changes added
  to it are caught only by review.
- The repository receives every absent parent default, including workflows it may not
  want, such as `release.yml`, which opens a release-please pull request after each push
  to `main`, and `dast.yml`. Removing one is a separate pull request, and a removed file
  that an inherited test requires fails `doctor` again.
- A repository with its own workflows under different names keeps them and also receives
  the parent's, so some checks run twice until the owner removes one set.
- Copied placeholders, such as `{{ORG}}` in `CODEOWNERS` and `{{PROJECT_NAME}}` in
  `.ai/mission.md`, stay until the owner replaces them.

**Migration and rollback:** repositories adopted before this decision are unaffected; their
hand ports are done. Rolling back removes the baseline step from activation and the
exception from `pr_size_policy.py`; repositories adopted in between keep the copied files,
which they own.

**Follow-ups:**

- Implement the baseline step, the `Taskfile.yml` payload, and the plan field in
  `scripts/template_inheritance.py`, with tests whose parent fixture ships protected files.
- Implement the exception in `scripts/pr_size_policy.py`, with tests.
- Update Scenario C in `docs/foundation/guides/usage.md` (phase 3 payloads, the baseline,
  the exemption, the follow-up edits) and the template-inheritance troubleshooting page.
